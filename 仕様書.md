## 1. システム概要

### 1-1. アプリ概要

ユーザーが入力した出来事・会話文・補足情報をもとに、
**相手の機嫌・感情傾向・温度感をポジティブ／ネガティブ両面から分析する AI Web アプリ**。

### 1-2. アプリの性質

| 項目       | 内容                                               |
| ---------- | -------------------------------------------------- |
| アプリ種別 | フォーム入力型（チャットアプリではない）           |
| 操作フロー | フォーム入力 → AI 分析 → 結果表示                  |
| 分析単位   | `AnalysisCase`（1 相談 = 1 件）                    |
| 人物管理   | 同じ人物に複数の `AnalysisCase` を追加可能         |
| 分析対象   | 怒り・不機嫌だけでなく、喜び・安心・前向きさも含む |

### 1-3. MVP で重視すること

- ハッカソン中に**確実に動くこと**
- フロント実装が迷わないこと
- 必須入力を最小限にすること
- 結果を見せる体験を最優先にすること
- 「悪い反応かもしれない」だけでなく「良い反応かもしれない」も返せること

## 4. セッション方針

### 4-1. sessionId の渡し方

**`POST /api/sessions` を除く全 API のリクエストヘッダーに `X-Session-Id` を必須とする。**
Cookie・クエリパラメータ・ボディでは渡さない。

(`X-Session-Id` も「標準の認証ヘッダー（`Authorization`）ではなく、自前のセッション識別用ヘッダーだ」と明示するために `X-` を付けている。)

```
X-Session-Id: sess_xxxxxxxxx
```

> **例外：** `POST /api/sessions` のみヘッダー不要。初回アクセス時にサーバーが新しい `sessionId` を発行する。

### 4-2. sessionId の保持場所

フロントでは `localStorage` に `sessionId` を保存する。

### 4-3. セッション有効期限

| 項目                   | 内容                         |
| ---------------------- | ---------------------------- |
| 有効期間               | 24 時間                      |
| 期限切れ時のレスポンス | `SESSION_INVALID (401)`      |
| フロント側対応         | 新しいセッションを再発行する |

### 4-4. 前提と注意

- `sessionId` は十分長いランダム文字列で生成する
- `sessionId` が漏れた場合、他人がアクセスできる可能性がある
- **本方式はハッカソン MVP 向けの簡易識別方式。本番認証ではない**

## 5. 共通エラー仕様

### 5-1. エラーレスポンス形式

すべてのエラーは以下の形式に統一する。

```json
{
    "error": {
        "code": "NOT_FOUND",
        "message": "指定されたリソースが存在しません",
        "status": 404
    }
}
```

### 5-2. エラーコード一覧

| コード              | 意味                                 | HTTP ステータス |
| ------------------- | ------------------------------------ | --------------- |
| `SESSION_INVALID`   | sessionId が無効・不存在・期限切れ   | 401             |
| `FORBIDDEN`         | 他セッションのリソースにアクセスした | 403             |
| `NOT_FOUND`         | person / case が存在しない           | 404             |
| `ALREADY_ANALYZING` | 分析中に再度 analyze を叩いた        | 409             |
| `ALREADY_ANALYZED`  | 分析済みのケースに analyze を叩いた  | 409             |
| `VALIDATION_ERROR`  | 入力バリデーション失敗               | 422             |
| `AI_TIMEOUT`        | AI API タイムアウト                  | 503             |
| `INTERNAL_ERROR`    | サーバー内部エラー                   | 500             |

### 5-3. 共通ルール

| 条件                                              | 返すエラー               |
| ------------------------------------------------- | ------------------------ |
| `POST /api/sessions` 以外で `X-Session-Id` がない | `SESSION_INVALID (401)`  |
| `X-Session-Id` が無効または期限切れ               | `SESSION_INVALID (401)`  |
| リソース所有セッションと不一致                    | `FORBIDDEN (403)`        |
| 入力不足・文字数超過                              | `VALIDATION_ERROR (422)` |

## 9. AI 出力仕様

### 9-1. 出力ブロック一覧

| #   | ブロック名             | フィールド                                                                       |
| --- | ---------------------- | -------------------------------------------------------------------------------- |
| 1   | 文面から見える印象     | `textImpression`                                                                 |
| 2   | 状況込みで見た印象     | `contextImpression`                                                              |
| 3   | 感情スコア             | `scoreAngry` / `scoreBusy` / `scoreJustCold` / `scorePositive` / `scoreDistance` |
| 4   | 分析の確信度           | `confidenceLevel`                                                                |
| 5   | コンタクトのタイミング | `contactTiming`                                                                  |
| 6   | 今取るべき行動         | `actionsJson`                                                                    |
| 7   | 避けるべき表現         | `avoidExpressionsJson`                                                           |
| 8   | ポジティブに見える要素 | `goodSignalsJson`                                                                |
| 9   | 返信例                 | `replyExamplesJson`                                                              |

### 9-2. 表示ルール

- 断定ではなく「可能性」で表現する
- ネガティブ面だけでなくポジティブ面も返す
- 返信例は複数返す
- スコアは `0.00〜1.00` の小数
- 確信度の UI 表示：`low` → 低 / `medium` → 中 / `high` → 高
- `contactTiming` は 200 文字以内

### 9-3. 分析方針

AI はユーザーの不安をそのまま事実として扱わない。以下を区別して分析する。

- 実際に起きた事実
- 会話文から読み取れる要素
- ユーザーの主観的な不安
- 相手の感情予想（ユーザーによる）
- 状況要因（忙しさ・関係性・普段の話し方）

**悪い兆候だけでなく、良い兆候も必ず拾う。**

### 11-2. POST /api/persons

**用途：** 分析対象人物を保存する。

**ヘッダー**

```
X-Session-Id: sess_001
```

**リクエスト**

```json
{
    "displayName": "上司A",
    "relationshipType": "boss",
    "ageRange": "40s",
    "genderHint": "male",
    "notes": "普段から短文寄り"
}
```

**レスポンス**

```json
{
    "person": {
        "id": "person_001",
        "displayName": "上司A",
        "relationshipType": "boss",
        "ageRange": "40s",
        "genderHint": "male",
        "notes": "普段から短文寄り",
        "createdAt": "2026-03-22T12:00:00.000Z"
    }
}
```

**バリデーション**

| フィールド         | ルール                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------- |
| `displayName`      | 必須、1〜50 文字                                                                            |
| `relationshipType` | 必須、`boss / coworker / lover / family / friend / classmate / customer / other` のいずれか |
| `notes`            | 任意、1000 文字以内                                                                         |

**ステータスコード**

| コード | 条件               |
| ------ | ------------------ |
| 201    | 成功               |
| 401    | session 不正       |
| 422    | バリデーション失敗 |
| 500    | サーバー異常       |

### 11-3. POST /api/analysis-cases

**用途：** 新しい AnalysisCase を作成する。

**ヘッダー**

```

```

**リクエスト**

```json

    "personId": "person_001",
    "eventFacts": "資料を送ったあと、相手から『確認します』だけ返ってきた",
    "selfMessage": "資料をお送りします。ご確認お願いします。",
    "partnerMessage": "確認します。",

    "appType": "slack",
    "userEmotion": "不安",
    "assumedPartnerEmotion": "怒っていそう",
    "partnerSpeakingStyle": "普段から短文",
    "contextNote": "締切前で忙しい時期",
    "concernText": "怒っているのか不安",
    "emojiUsed": false,
    "toneType": "formal",
    "messageLengthType": "short"
}
```

**レスポンス**

```json
{
    "analysisCase": {
        "id": "case_001",
        "personId": "person_001",
        "status": "draft",
        "createdAt": "2026-03-22T12:10:00.000Z"
    }
}
```

**バリデーション**

| フィールド               | ルール                                               |
| ------------------------ | ---------------------------------------------------- |
| `personId`               | 必須                                                 |
| `eventFacts`             | 必須、1〜3000 文字                                   |
| `selfMessage`            | 必須、1〜3000 文字                                   |
| `partnerMessage`         | 必須、1〜3000 文字                                   |
| `recentConversationText` | 任意、5000 文字以内                                  |
| `toneType`               | 任意、`formal / casual / mixed / unknown` のいずれか |
| `messageLengthType`      | 任意、`short / normal / long / unknown` のいずれか   |
| その他の任意項目         | 1000 文字以内を目安に制限                            |

**ステータスコード**

| コード | 条件                  |
| ------ | --------------------- |
| 201    | 成功                  |
| 401    | session 不正          |
| 403    | 他セッションの person |
| 404    | person 不存在         |
| 422    | バリデーション失敗    |
| 500    | サーバー異常          |

### 11-4. POST /api/analysis-cases/:caseId/analyze

**用途：** AnalysisCase をもとに AI 分析を実行する。

**ヘッダー**

```
X-Session-Id: sess_001
```

**リクエスト**

```json
{}
```

**AI に渡すフィールド**

```
Person       : displayName, relationshipType, ageRange, genderHint, notes
AnalysisCase : eventFacts, selfMessage, partnerMessage, recentConversationText,
               appType, userEmotion, assumedPartnerEmotion, partnerSpeakingStyle,
               contextNote, concernText, emojiUsed, toneType, messageLengthType
```

**処理方針**

- MVP では**同期処理**とする（AI 完了まで待ってからレスポンスを返す）
- タイムアウト：15,000 ms
- 自動リトライ：なし（デモ中に待ち続ける事故を避けるため）

**二重実行防止・再実行ルール**

| ケース status | 挙動                                                   |

| `draft`       | analyze 開始 → status を `analyzing` に更新            |

| `analyzed`    | `ALREADY_ANALYZED (409)` を返す（再分析は MVP 対象外） |

## 12. 状態遷移

```
draft     ──[analyze 開始]────→ analyzing
analyzing ──[analyze 成功]────→ analyzed
analyzing ──[analyze 失敗]────→ error
error     ──[analyze 再実行]──→ analyzing
```

| 遷移元 status | 操作               | 遷移先                             |
| ------------- | ------------------ | ---------------------------------- |
| `draft`       | analyze 実行       | `analyzing`                        |
| `analyzing`   | 成功               | `analyzed`                         |
| `analyzing`   | 失敗・タイムアウト | `error`                            |
| `error`       | analyze 再実行     | `analyzing`                        |
| `analyzed`    | analyze 実行       | `ALREADY_ANALYZED (409)` ※遷移なし |

**補足**

- MVP では analyze が同期処理なので、`analyzing` を長時間維持しない
- 二重実行防止のため `analyzing` 状態は DB に保持する
- 再分析専用 API は MVP では実装しない

## 13. フロント実装ルール

### 13-1. localStorage に保存するもの

- `sessionId`
- 最後に開いていた `personId`
- 最後に開いていた `caseId`

### 13-2. localStorage に保存しないもの

- 分析履歴本体
- AI 生レスポンス全文
- 個人情報に近い長文

### 13-3. SESSION_INVALID 受信時の動き

`SESSION_INVALID (401)` を受けたら：

1. `POST /api/sessions` で新規セッションを取得
2. `localStorage` の `sessionId` を更新
3. 必要なら最初の人物選択画面へ戻す

### 13-4. analyze 実行時の動き

| ステップ | 処理                                                               |
| -------- | ------------------------------------------------------------------ |
| 1        | `POST /api/analysis-cases/:caseId/analyze` を叩く                  |
| 2        | レスポンスが返るまでローディング表示                               |
| 3        | 成功（200）→ 結果画面へ遷移                                        |
| 4        | `503` → 「時間がかかりました。再試行してください」と表示           |
| 5        | `409 ALREADY_ANALYZING` → 「分析中です」と表示して重複送信を止める |
| 6        | `409 ALREADY_ANALYZED` → 「このケースはすでに分析済みです」と表示  |

### 13-5. ケース status 別の表示方針

| status      | 一覧のバッジ | 詳細画面のボタン                         |
| ----------- | ------------ | ---------------------------------------- |
| `draft`     | 「未分析」   | 「分析する」→ `POST /analyze` を実行     |
| `analyzing` | 「分析中」   | ローディング表示（ボタンなし）           |
| `analyzed`  | 「分析済み」 | 結果を表示するだけ（ボタンなし）         |
| `error`     | 「分析失敗」 | 「再試行する」→ `POST /analyze` を再実行 |

## 14. セキュリティ最低限ルール

1. `sessionId` は十分長いランダム文字列で発行する
2. 他セッションの `personId` / `caseId` へのアクセスは必ず `403` を返す
3. AI の生レスポンス（`rawAiResponse`）は保存しない
4. 個人情報を書きやすい自由記述欄は最小限にする
5. AI 入力前に極端に長いテキストは切り詰める
6. 「相手の感情予想」はユーザーの主観として扱い、事実として AI に渡さない

> `sessionId` 方式は本人確認ではなく簡易識別方式。本番公開時は正式な認証方式への移行を検討すること。
