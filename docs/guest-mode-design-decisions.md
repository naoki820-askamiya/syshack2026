# ゲスト1回の設計判断と検証記録

登録前に価値を試せる導線について、匿名利用の費用・所有権・障害境界に関する設計判断と、2026-10-21の作業時の検証記録をまとめます。既定OFFの実装であり、本番導入・課金削減・登録率改善の実績は含みません。検証結果は当時の作業報告に記載されたもので、今回の文書整理で再実行したものではありません。

## 設計判断

- Cookieは人間の本人性を保証しません。「1人1回」ではなくサーバー発行利用権あたり最大1送信とし、Cookie削除・別端末の限界は全体金額・総件数・同時枠で受け止めます。
- DB transactionと外部providerを同時commitできないため、exactly-once成功を約束しません。送信許可を永続化し、そのcommitを確認した実行者だけが送信します。直後のcrashで実送信0回でも利用権を失い得る、at-most-onceの選択です。
- 利用権、最大費用、件数、同時枠を同じ予算lockとtransactionで予約します。複数instance、複数tab、再送をUIのdisableだけに依存させません。
- timeoutを未課金の証拠にしません。UNKNOWNは最大費用・同時枠を保持して受付停止します。v1は成功時も最大予算占有を維持し、実請求と予算占有を分け、未検証の返金機構を作りません。
- 本文の削除と利用済み記録を分離します。削除印と期限の条件付き保存で、削除後の遅い完了による本文復活を防ぎます。
- ゲストは通常の人物・履歴・Feedbackへ接続せず、登録後の通常枠と分けます。結果を登録の条件にせず、自動引継ぎ・credit統合も行いません。
- 承認済みmodel/価格/token計数/同意releaseがない状態はfail closedにし、環境変数の推測値で本番を有効化しません。

## 検証範囲と限界

検証対象は「合成providerへの実HTTP受信数」「50並列の同じ利用権」「予算競合」「許可commit応答消失」「UNKNOWN」「削除と遅延完了」などです。実PostgreSQLテストのコードがあることと実行成功は区別します。実モデル品質、安全性、本番Cookie/RLSや運用の合格へ一般化しません。

検証結果は対象commitと実行済みテストの範囲に限定し、実DB/E2Eの未検証、既定OFF、本番未導入を区別します。仮TTL・仮予算は承認済み運用値ではありません。

2026-10-21の作業検証では、通常側回帰を含む566テスト、型検査、client/server buildが成功しました。実SDKからlocalhost fake HTTPへの50並列でも受信は1回でした。実Reactの画面で、OFF、Cookie往復、合成入力・結果、停止後の状態取得、削除と再取得、任意登録リンクを確認しました。実モデル・実Auth・実PostgreSQL・本番Cookie/権限は未検証です。追加した実DB受入テスト21件はDocker利用不可のため未実行で、スマホ幅指定も反映されず実寸確認は未検証です。これらの結果は本番導入の実績を示しません。
